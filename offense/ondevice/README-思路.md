# 攻击侧（思路级说明）

> 本目录只保留攻击**思路与原理**，不含可运行实现。完整工程仅授权范围离线交付，请勿在公开渠道分发。

## 三条技术路线（概念）

| 路线 | 思路 | 适用 |
|---|---|---|
| 系统 mock provider | 通过开发者选项把虚拟位置 App 设为模拟位置源，写入 gps provider | 原生 LocationManager 系目标（无原生定位 SDK） |
| 注入改写 | 免 root 重打包：壳完整性/证书校验绕过 + 定位 SDK 回调改写 + 读取虚拟环境位置 | 高德/百度原生融合定位系目标（如华中大体育） |
| 容器虚拟化 | 免 root 容器承载原版 App，容器层喂无 mock 标志位置 | 概念路线；公开框架对新 Android 兼容性有限，见评估 |

## 定位读取改造核心思路（对应"强制读虚拟环境"）

目标 App 使用高德定位 SDK 6.6.0 原生融合定位，默认过滤系统 mock：
1. 让 App 进程启动时加载一个随包分发的位置改写器；
2. 改写器拦截 AMapLocationListener 回调，把坐标覆写为虚拟环境（系统 mock provider）写入的当前位置；
3. 同时把 isMock 类标志恒置 false、定位类型标记为 GPS；
4. 壳侧四类自杀/校验按判定点逐一中和（详见 docs/ 与 defense/ 的对照）。

## 通用化

- ABI：32 位(armeabi-v7a)与 64 位(arm64-v8a)目标共用同一逻辑，仅改写器载体按 ABI 选择；
- 定位系：高德/百度/原生三系 hook 面与判定树见 docs/01-threat-model.md；
- 任何校园跑 App 均可按同一模式接入虚拟环境。
