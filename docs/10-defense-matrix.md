# 10 · 攻防全景矩阵（每一种模式 → 每一种对应方案）

> 本文是 CampusRunShield 的**总索引**：把校园跑类应用的完整攻击面拆成 8 层、50 种攻击模式，
> 每一种给出「攻击手法 → 检测信号 → 客户端防御 → 服务端防御 → 绕过后下一步 → 残留风险」。
> 每一条都来自本仓库实测记录（62 个 release 的攻防对抗）或公开研究，可直接作为加固验收清单使用。
> 代码组件索引见 §11；各专题深挖见 docs/11–15。

## 图例

- **攻**：攻击者实际可执行的手法（本仓库 offense/ 仅保留思路级描述，不提供成品）
- **检**：检测该攻击的信号（日志、文件系统、运行时痕迹）
- **防C**：客户端（App 内）防御
- **防S**：服务端防御
- **绕**：攻击者绕过该防御的下一步手法（用于自我审计，不是教唆）
- **余**：即便上述全做，仍残留的风险与最终兜底

---

## 0. 分层总览

```
┌─ L1 静态包体层   ─ 重打包/重签名/资源篡改/资产提取
├─ L2 壳与加载层   ─ 签名校验/完整性校验/解密落盘/自刀/守卫
├─ L3 运行时注入层 ─ Frida/Xposed/ClassLoader 钩子/线程干扰
├─ L4 定位伪造层   ─ mock provider/getter 覆写/回调替换/坐标转换
├─ L5 数据轨迹层   ─ 轨迹点替换/速度钳制/距离伪造/上报注入
├─ L6 传输协议层   ─ 请求签名/重放/中间人/证书固定
├─ L7 服务端判定层 ─ 轨迹合理性/配速模型/行为分析/证据校验
└─ L8 环境与账号层 ─ root/模拟器/多开/账号风控
```

**核心原则：任何单层被破都不等于失守。** 本仓库全部防御按"单层被破仍能止损"设计。

## 1. L1 静态包体层

### M1 重打包 + 重签名（apktool 解码 → 篡改 → 重签）
| 项 | 内容 |
|---|---|
| 攻 | `apktool d` 解码、注入 smali/资产、`apktool b` 重建、任意 keystore 重签（v1+v2+v3） |
| 检 | 签名证书指纹 ≠ 发布指纹；`lastUpdateTime` 突变；安装来源非商店；资源表 arsc 重新生成特征 |
| 防C | ①启动时校验自身签名（对比内置硬编码指纹，见 IntegrityGuard.kt）；②重要资产加密（csn 方案：dex 加密为资产，密钥不进 Java 层）；③资源防篡改校验（抽查 arsc 哈希） |
| 防S | 登录/上报接口携带签名摘要，服务端比对发布指纹白名单 |
| 绕 | sig-spoof：hook `getPackageInfo` 把 signatures 换回原证书（见 M4） |
| 余 | 校验逻辑本身在客户端，可被 hook；只能提高成本，无法杜绝 |

### M2 资产提取与离线分析（解包 assets、so、加密资产）
| 项 | 内容 |
|---|---|
| 攻 | 直接解包读取 `assets/csn*.data`、`orig.apk`、so、配置 |
| 检 | 无法检测（离线行为） |
| 防C | 敏感资产加密存储 + 密钥由运行时指纹派生（设备+签名+时间窗），静态提取只得到密文 |
| 防S | 协议层加签名/加密，裸资产不构成完整攻击能力 |
| 绕 | 动态脱壳/内存 dump（见 M12） |
| 余 | 客户端资产最终必然可被有经验攻击者恢复，防线重心后移 L5-L7 |

### M3 资源重建伪装（aapt2 重编资源、同尺寸 padding）
| 项 | 内容 |
|---|---|
| 攻 | 重建 apk 后用 padding 对齐原尺寸、仿造 zip 结构 |
| 检 | arsc 打包器版本/条目顺序/压缩算法指纹异动；zip 注释字段 |
| 防C | 校验自身 apk 的 zip 中央目录哈希（覆盖 assets 关键条目） |
| 防S | 不依赖"包体完全一致"假设；核心判定在服务端 |
| 绕 | 同哈希攻击成本极高，攻击者转而攻 L2-L4 |
| 余 | 略 |

### M4 证书欺骗（sig-spoof）
| 项 | 内容 |
|---|---|
| 攻 | hook `ApplicationPackageManager.getPackageInfo`，将 `signatures` 替换为原版证书 DER |
| 检 | Java 层 `PackageManager` 返回值被篡改无痕；但 `PackageManagerService` 侧（服务端进程）真实值未变 |
| 防C | ①不走 Java API：native 层直接 `PackageManagerService` binder 或 `/proc` 侧取签名；②双重来源比对（Java 返回值 vs native 计算结果不一致即告警）；③校验签名用到的字符串混淆，防 grep 定位 |
| 防S | 请求头带签名摘要，服务端比对 |
| 绕 | 攻击者同时 hook native 校验函数（见 M10） |
| 余 | 签名校验终归是"比较"，比较点全都能 hook；应叠加行为风控 |

### M5 防篡改分支 NOP 化
| 项 | 内容 |
|---|---|
| 攻 | 在 native 校验函数中定位比较/跳转指令，直接 NOP 篡改分支（同尺寸原地补丁） |
| 检 | 自身 so 的哈希变化；代码段只读属性被解除 |
| 防C | ①启动时计算自身关键 so 的段哈希（mmap 后自检）；②校验结果不直接布尔化：把结果参与后续解密密钥派生（校验被 NOP → 解密密钥错误 → 功能自毁而非静默放行）；③关键比较分散多份、跨进程 |
| 防S | 与 M1/M4 同：签名摘要上送 |
| 绕 | 攻破密钥派生链（成本高一个量级） |
| 余 | 略 |

### M6 重签名后的原生 abort 与自毁点
| 项 | 内容 |
|---|---|
| 攻 | 观察崩溃栈定位壳的自毁点，提前 hook/绕过 |
| 检 | 崩溃埋点被触发说明存在篡改 |
| 防C | 自毁逻辑 VMP 化/多份冗余；自毁前先上报设备指纹（服务端拉黑） |
| 防S | 收到"篡改上报"→ 冻结账号/设备，让绕过者白忙 |
| 绕 | 攻击者拦截上报（见 L6） |
| 余 | 略 |

## 2. L2 壳与加载层

### M7 壳解密落盘窗口攻击（dex 解密后落盘瞬间抢拷贝）
| 项 | 内容 |
|---|---|
| 攻 | hook `File.delete`/`unlink`/`unlinkat`，在壳删除解密 jar 前拷走 |
| 检 | 无直接检测；属于必然风险 |
| 防C | ①不落盘：`InMemoryDexClassLoader` + 内存字节喂 ART；②必须落盘时用 O_TMPFILE/加密文件系统特性、用完立即 `unlink` 且文件打开期间不可读（O_EXCL）；③落盘文件名随机 + 目录权限 0700 |
| 防S | 无 |
| 绕 | 内存 dump（见 M12） |
| 余 | ART 层 dump 难以完全防住；重心在 L5-L7 |

### M8 状态污染攻击（残留解密文件复用导致崩溃/降级）
| 项 | 内容 |
|---|---|
| 攻 | 早期失败运行留下截断/损坏的 `libdsn_*.jar`，文件名哈希固定 → 后续启动复用坏文件 → "Invalid file" 崩溃（实测触发） |
| 检 | 崩溃侧可见 `DexFile.openDexFileNative: Invalid file` |
| 防C | ①落盘 jar 使用前先校验长度与头部魔数；②文件名哈希加入随机盐（每次启动不同）；③异常路径统一清理临时文件 |
| 防S | 无 |
| 绕 | 无（这是防崩类防御，非对抗点） |
| 余 | 略 |

### M9 文件读取重定向（open/openat 换路径）
| 项 | 内容 |
|---|---|
| 攻 | hook libc `open`/`openat`，把对 `base.apk` 的读取重定向到攻击者放置的原版 apk，配合 stat 伪造骗过校验 |
| 检 | `/proc/self/maps` 出现可疑注入模块；open 频率异常 |
| 防C | ①校验逻辑不读自身 apk 文件，改读内存映射；②对自身 apk 做 `pread` 全文哈希，路径被换则哈希必变；③native 层用 syscall 直调（绕过 libc 符号 hook）；④关键文件用 `openat2` + `RESOLVE_BENEATH` 防路径欺骗 |
| 防S | 无 |
| 绕 | hook syscall 层/`svc` 指令级 hook（成本高） |
| 余 | 略 |

### M10 stat 尺寸伪造
| 项 | 内容 |
|---|---|
| 攻 | hook `stat`/`fstat` 家族，把 st_size 伪造成原包大小，配合 M9 使用 |
| 检 | stat 与 read 结果不一致（防御侧自查） |
| 防C | 校验时用"读多少信多少"（以实际读取字节计算哈希），不信 st_size |
| 防S | 无 |
| 绕 | 攻击者同步伪造内容长度 |
| 余 | 略 |

### M11 csn 资产完整性（EXIT_SELF）
| 项 | 内容 |
|---|---|
| 攻 | 篡改加密资产（dex 补丁），期望绕过校验；实测壳以 `EXIT_SELF` 秒杀 |
| 检 | 壳自身行为（已防御成功） |
| 防C | ①资产哈希/尺寸校验（本次对抗证明有效）；②校验失败不报错、静默延时自毁（防攻击者用崩溃定位校验点）；③解密密钥与资产哈希绑定（篡改 → 解出垃圾 → 类加载失败） |
| 防S | 无 |
| 绕 | 保持资产尺寸/哈希双不变的同尺寸字节补丁（见 M12） |
| 余 | 略 |

### M12 同尺寸字节级 dex 补丁
| 项 | 内容 |
|---|---|
| 攻 | 不重编译 dex，直接在原始 jar（STORED 无压缩条目）内做等长指令补丁（改 invoke 目标/寄存器），绕过尺寸与结构校验 |
| 检 | dex 内容哈希变化（若只校验尺寸则测不出） |
| 防C | **必须校验内容哈希而不是尺寸**；条目存储用 deflate 使等长补丁改变压缩输出尺寸；定期抽查 code_item |
| 防S | 无 |
| 绕 | 攻击者需同时伪造哈希校验点（回 M4/M5 循环） |
| 余 | 略 |

### M13 多进程守卫与 kill 自刀
| 项 | 内容 |
|---|---|
| 攻 | hook `kill`/`tgkill` 屏蔽壳的自杀信号；hook 守卫线程入口 `_me_.a.run` 让校验空转 |
| 检 | 无自刀行为本身即异常信号（服务端收不到心跳上报） |
| 防C | ①守卫进程双向心跳：主进程死亡 → 守卫复活/上报；守卫死亡 → 主进程延时自毁；②自刀用 `syscall(SYS_kill)` 直调绕过 libc hook；③校验结果经多路径冗余（Java/native/跨进程）互相印证 |
| 防S | 心跳缺失 → 风控降权 |
| 绕 | syscall 级 hook；或整进程替换（改机） |
| 余 | 略 |

### M14 JNI 异常吞吃（ThrowNew 劫持）
| 项 | 内容 |
|---|---|
| 攻 | 修改 JNI 函数表 `ThrowNew` 表项（offset 14×ptr），吞掉壳抛出的篡改异常 |
| 检 | 函数表项地址 ≠ libart 导出符号（自检） |
| 防C | ①启动时校验 JNIEnv 函数表关键项指针在 libart 段内；②异常路径不依赖 JNI 异常传播：用返回值错误码 + 独立自毁 |
| 防S | 无 |
| 绕 | 攻击者改用其他异常通道（Java throw） |
| 余 | 略 |

### M15 类加载钩子递归陷阱（防御视角：攻击者自伤）
| 项 | 内容 |
|---|---|
| 攻 | 攻击者 hook `ClassLoader.loadClass/findClass` 以捕获业务 loader；若实现为"wrapper 内再调 this.loadClass"，会在壳自定义 findClass 的 super 链上形成递归 → 栈溢出闪退（实测攻击者连续两版因此自爆） |
| 检 | 应用自身无感；攻击者侧崩溃 |
| 防C | 壳自定义 loader 覆盖 `findClass`（解密）本身就是天然反 hook 结构：任何粗心的基类 hook 都会递归；可主动加深：loader 内再套一层代理 |
| 防S | 无 |
| 绕 | 攻击者改用 DexClassLoader 构造器钩子/Instrumentation 钩子捕获（需防：构造器加混淆、延迟构造） |
| 余 | 略 |

## 3. L3 运行时注入层

### M16 Frida Gadget 改名注入
| 项 | 内容 |
|---|---|
| 攻 | 把 libgadget.so 改名 libXXX.so 塞进 lib/，manifest/smali 注入 loadLibrary，脚本模式零端口 |
| 检 | ①lib 目录出现非官方 so；②`/proc/self/maps` 出现异常模块路径；③so 导出符号/字符串含 frida 特征（即使改名）；④加载顺序异常（应用最早期加载未知 so） |
| 防C | ①启动时扫 `maps` 全部模块路径与官方清单比对；②扫内存字符串特征（frida/gadget/gum）；③校验 lib 目录内每个 so 的签名（官方签名清单）；④重要逻辑延迟到"环境干净"之后 |
| 防S | 无 |
| 绕 | gadget 重编译去特征、内存擦字符串、magisk 隐藏 |
| 余 | 环境检测永远可绕，叠加 L4-L7 |

### M17 smali 自提取脚本
| 项 | 内容 |
|---|---|
| 攻 | 把 hook 脚本作为资产随包分发，smali 代码启动时解出到 files/，gadget 读取执行 |
| 检 | 资产清单出现脚本文件；files/ 出现非预期文件 |
| 防C | 启动后扫描自身 files/ 与资产清单，未知文件上报 |
| 防S | 无 |
| 绕 | 脚本改名/内存加载 |
| 余 | 略 |

### M18 ClassLoader 捕获（构造器/Instrumentation 钩子）
| 项 | 内容 |
|---|---|
| 攻 | hook `DexClassLoader.$init`、`Instrumentation.callApplicationOnCreate/newApplication`、`Application.onCreate` 捕获业务 loader（M15 递归陷阱的正解） |
| 检 | 上述 bootstrap 方法被 hook 后调用频率/来源异常（自检无直接信号） |
| 防C | ①业务 loader 用私有子类（构造混淆名），延迟创建；②Application 实例化走 AppComponentFactory（系统回调）而非可预测路径；③核心类名字符串加密，hook 者无法按名匹配 |
| 防S | 无 |
| 绕 | 任意类对象反查 loader（无法杜绝） |
| 余 | 略 |

### M19 类枚举挂死攻击面（enumerateClassLoaders 间歇性挂死）
| 项 | 内容 |
|---|---|
| 攻 | 攻击者脚本频繁 `Java.enumerateClassLoaders`/`enumerateLoadedClasses`，在 ART 与壳 loader 组合下间歇性挂死脚本线程（实测：多次枚举后 JS 事件循环冻结） |
| 检 | 无（攻击者自伤） |
| 防C | 保持应用类加载路径稳定（减少动态 loader 增删），加大攻击者枚举的不稳定性；日志埋点观察"异常静默" |
| 防S | 无 |
| 绕 | 攻击者改用事件驱动（构造器钩子）捕获，避开枚举 |
| 余 | 略 |

### M20 Java 层方法钩子（Java.use + implementation）
| 项 | 内容 |
|---|---|
| 攻 | 覆写关键 getter/setter、拦截器、构建器（本次实测：AMapLocation getter、UploadJsonSports.build、SportBean.getDistance 均被覆写） |
| 检 | 方法入口 ArtMethod 入口点与 dex 定义不符（native 自检可扫描）；方法调用耗时分布异常（hook 有开销） |
| 防C | ①关键方法 native 化（把逻辑移入 so）；②关键值不信任"调用链终点"——在 native 层重复计算并比对；③方法哈希自检（遍历类方法入口与内置表比对）；④关键类不暴露稳定符号（混淆/proguard 开满） |
| 防S | 服务端交叉校验数据（见 L7） |
| 绕 | native 层 hook（M23）；inline hook 更底层 |
| 余 | 客户端终究可被完全控制，L7 是唯一终局 |

### M21 定时器/事件循环干扰与脚本自检
| 项 | 内容 |
|---|---|
| 攻 | 攻击者脚本常因同步 IO/枚举/递归自死（本次实测三类：目录遍历卡死、枚举挂死、钩子递归） |
| 检 | 无 |
| 防C | 应用侧主动制造攻击者脚本不稳定性：高频类加载抖动、超大 assets 目录、FUSE 路径探测惩罚 |
| 防S | 无 |
| 绕 | 攻击者工程化自检（心跳、异步化、去枚举） |
| 余 | 略 |

### M22 Xposed/LSPosed 模块（如 MokrRun）
| 项 | 内容 |
|---|---|
| 攻 | 系统级模块钩子（无需改包）；社区已有校园跑模块 |
| 检 | ①`/proc/self/maps` 出现 xposed 模块 so；②堆栈出现 XposedBridge；③ClassLoader 链含 xposed；④native 层读取 `/proc/self/task/*/comm` 或检测注入线程 |
| 防C | 同 M16 环境检测 + `de.robv.android.xposed` 类探测 + maps 白名单 |
| 防S | 设备指纹异常（系统框架被改） |
| 绕 | 隐藏框架（Shamiko 类） |
| 余 | 略 |

### M23 native 层 hook（inline hook / RegisterNatives 劫持）
| 项 | 内容 |
|---|---|
| 攻 | ①inline hook so 内函数（本次实测攻击方计划劫持 `convertToGcj` 坐标转换参数）；②hook `RegisterNatives` 表项替换实现 |

| 防S | 无 |
| 绕 | 字节级还原/换点 hook |
| 余 | 略 |

### M24 内存 dump 与脱壳（进程内存/ART 层抓取）

## 10. 校园跑场景落地清单（防御方按此验收）

1. **包体**：v1+v2+v3 签名 + 启动签名自检（native 取真值）+ 关键资产加密。
2. **壳**：业务 dex 加密、内存加载优先、落盘防删（unlink 即删 + 哈希校验 + 随机盐文件名）。
3. **环境**：root/模拟器/mock 设置/frida/Xposed 五类检测，结果分档（正常/可疑/高危）。
4. **定位**：系统 provider 层 mock 过滤 + SDK 层双重比对 + 新鲜度校验（>5min 丢弃）。
5. **数据**：关键 getter/落库/上传三处交叉一致性校验（native 计算）。
6. **协议**：请求签名绑定时间窗+设备+账号 + 心跳。
7. **服务端**：完整轨迹证据强制提交 + 重算距离 + 形态学（方差/自相关/贴路率/重复检测）+ 配速模型。
8. **风控**：设备-账号图谱、成绩可信度降权、满分人工复核、惩罚梯度。
9. **对抗预算**：以上每层可绕，预期是把攻击成本推到"不值得"，而非绝对防御。
10. **回滚**：所有校验失败走"静默降权 + 上报"而非"崩溃报错"（防崩溃点被用于定位校验逻辑）。
