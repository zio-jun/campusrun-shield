# 15 · 纵深防御与验收手册

> 单点防御必然被绕过。本文给出纵深防御的工程框架、成本模型与验收清单，
> 目标不是"绝对安全"，而是把攻击者的单次作弊成本推到收益之下。

## 1. 分层与容错模型

```
L1 包体(签名/资产加密)     ← 破 →  L2 壳(完整性/自毁/守卫)  ← 破 →
L3 运行时(反注入/反调试)   ← 破 →  L4 定位(反 mock/字段对账) ← 破 →
L5 数据(交叉校验/证据链)   ← 破 →  L6 协议(签名/心跳)       ← 破 →
L7 服务端(形态学/风控)     ← 破 →  L8 账号(图谱/人工复核)
```

原则：
1. **每层独立可验**：层与层不共享判断结果，任一单点被 NOP 不影响他层。
2. **失败即降权**：检测触发不崩溃、不弹窗，只上报 + 服务端降权——避免暴露检测点。
3. **终局在服务端**：客户端所有校验仅用于"提高成本"，真伪判定只在服务端。

## 2. 攻击成本模型（设计预算）

| 层级 | 绕过成本（经验值） | 防御投入 |
|---|---|---|
| L1–L2 包体/壳 | 中（数天逆向） | 加固 SDK 或自研壳 |
| L3 运行时注入 | 低→中（现成工具） | 多信号检测 |
| L4 定位伪造 | 低（公开路线 App） | 字段对账 + 新鲜度 |
| L5 数据篡改 | 中（需自洽） | 证据链 + 交叉校验 |
| L6 协议 | 高（VMP 签名） | 签名/心跳 |
| L7 服务端 | 高（需形态学建模） | 算法 + 数据积累 |
| L8 账号 | 极高（换号成本） | 图谱 + 人工 |

目标配置：让"代跑一次"的总成本 > 真实跑一次的成本。

## 3. 客户端验收清单

- [ ] 启动签名自检（native 取真值，非 Java 返回值）
- [ ] 关键 so/资产内容哈希自检（非尺寸）
- [ ] 业务 dex 加密 + 内存加载优先；落盘防删 + 随机盐文件名
- [ ] 自毁走 syscall 直调；守卫双向心跳；心跳缺失上报
- [ ] 检测分档（正常/可疑/高危）+ 静默上报，无即时崩溃
- [ ] maps/字符串/JNI 表/入口字节 四类注入检测
- [ ] mock 位 native 直读 + 多 provider 交叉
- [ ] 关键 getter/落库/上传 三处一致性对账
- [ ] 定位新鲜度校验（>5min 丢弃，elapsedRealtime 计算）
- [ ] 请求签名绑定时间窗+设备+账号；关键接口证书固定

## 4. 服务端验收清单

- [ ] 强制完整轨迹证据，缺失拒收
- [ ] 距离/配速/用时 重算 + 一致性方程组
- [ ] 速度分布/熵/自相关 形态学特征
- [ ] 重复轨迹与团伙聚类（DTW/哈希）
- [ ] 设备-账号图谱 + 环境标记降权
- [ ] 满分/异常成绩自动人工复核
- [ ] 惩罚梯度 + 申诉通道

## 5. 运营手册（上线后）

1. **基线采集**：上线前用真实用户轨迹建基线（速度分布、熵、贴路率）；
2. **灰度**：新规则先标记后拦截，观察误伤率 < 0.5%；
3. **反馈闭环**：人工复核结果回流训练，月度迭代阈值；
4. **对抗演练**：定期用本仓库 offense/ 思路做红队自测，验证检测仍有效；
5. **透明度**：面向用户公示"作弊行为处理规则"，降低申诉成本。
