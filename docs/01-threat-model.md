# 01 · 威胁模型

## 1. 受保护资产

| 资产 | 说明 | 被攻击后果 |
|---|---|---|
| 跑步成绩数据 | 里程/时长/配速/轨迹/有效判定 | 学分造假、体测成绩失真 |
| 学分与评优 | 校园跑达标与体育成绩挂钩 | 公平性受损、学校公信力下降 |
| 用户隐私 | 位置、人脸、设备信息 | 数据滥用、合规风险 |
| 服务端判定逻辑 | 超速/步频/人脸等规则 | 规则泄露后被针对性规避 |

## 2. 攻击者画像

| 画像 | 能力 | 动机 | 典型手段 |
|---|---|---|---|
| 个人学生（低门槛） | 会装 APK、找教程 | 过线、拿学分 | 虚拟定位 App、代跑、模拟器 |
| 代跑灰产（中高门槛） | 有脚本/设备池 | 牟利 | 批量虚拟环境、轨迹模板、多设备 |
| 安全研究者 | 逆向/注入 | 评估防护 | 本项目的两种方式 |

## 3. 攻击面

```
位置来源链： GPS/北斗芯片 → 系统 LocationManager → 高德融合定位 SDK → 业务 SportLocationService → 服务端
传感器链：   加速度计/陀螺仪/计步传感器 → SensorManager → 业务步频统计 → 服务端
人脸核验链： 相机 → 活体检测(壳内 libchingo_face) → 服务端比对
网络链：     HTTPS 请求 → 服务端接口 → 成绩库
客户端完整性：APK 签名 / classes.dex / 资源 / 壳(DA2Lock)
```

对应两种攻击方式：
- **方式一（本机虚拟环境改造）**：在进程内 Hook 位置来源链的 SDK 层——不碰系统、不 root。
- **方式二（虚拟机 + 虚拟环境）**：整机虚拟化，可同时伪造位置链与传感器链，摄像头亦可注入。

## 4. 攻击目标与成功判据

| 目标 | 判据 | 本项目实测 |
|---|---|---|
| 让 App 显示假轨迹 | 地图轨迹与目标路线一致 | 方式一可达成（定位层替换） |
| 让成绩通过服务端校验 | 有效成绩入库 | 取决于服务端交叉校验强度 |
| 绕过客户端检测 | 不触发 mock/注入/完整性检测 | 壳有 dex 完整性校验，实测触发 |
| 绕过人脸核验 | 通过活体检测 | 方式一不可行；方式二需虚拟摄像头+活体对抗，难度高 |

## 5. STRIDE 简表

| 威胁 | 实例 | 主要防线 |
|---|---|---|
| Spoofing（伪装） | 虚拟定位、模拟器 | 环境一致性、设备认证 |
| Tampering（篡改） | Hook SDK、重打包 | 完整性自校验、注入检测、native 化 |
| Repudiation（抵赖） | 成绩争议 | 证据链（心跳+抽查+签名） |
| Information Disclosure | 密钥/接口泄露 | 白盒化、最小暴露 |
| DoS | 刷接口 | 限流、风控 |
| Elevation of Privilege | 越权改成绩 | 服务端鉴权 + 交叉校验 |

## 6. 防护非目标

- 不追求"零作弊"：不可能三角（体验、成本、强度）下追求**可度量、可运营**的防护。
- 不以牺牲隐私/体验换强度：移动端检测只做信号采集与分层处置。
