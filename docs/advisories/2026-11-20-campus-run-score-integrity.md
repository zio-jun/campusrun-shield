| 项目 | 内容 |
|---|---|

| 受影响组件 | 成绩提交接口（`https://tyapp.chingo.cn/cgapp/`） |
| 漏洞类型 | 业务逻辑缺陷 —— 数据完整性校验缺失 |
| 自评等级 | 中危 |

## 摘要

校园体育打卡类系统的成绩数据，其完整性完全依赖客户端防护：
客户端加固可被系统性绕过（客户端可被完全控制），而服务端不校验客户端完整性、
不重算轨迹证据。二者叠加导致"无需真实运动即可提交合格成绩"的风险。

## 影响

1. **成绩公平性**：体育成绩/学分可被低成本伪造；
2. **平台公信力**：同类平台多为多校共用，缺陷影响面不止单校；
3. **合规风险**：伪造成绩若被用于评奖评优等场景，将造成实质不公。

## 技术背景（防御视角）

- 商业加固（VMP 壳）能抬高逆向与注入成本，但**不能替代服务端校验**；
- 成绩数据的可信链应止于服务端：客户端的一切结论都不可信；
- 现有缺陷的根因不在"壳被破解"，而在**服务端缺少证据校验与重算**。

## 缓解与修复建议

| 优先级 | 措施 |
|---|---|
| P0 | 强制提交完整轨迹证据（点序列 + 时间戳 + 定位来源），服务端重算里程/配速并交叉校验，缺失或矛盾即拒收 |
| P1 | 提交接口请求签名（绑定设备指纹 + 时间窗 + 账号），关键接口证书固定 |
| P1 | 服务端轨迹形态学检测（速度分布 / 熵 / 自相关 / 贴路率 / 重复轨迹聚类），异常成绩人工复核 |
| P2 | 客户端纵深防御（签名自检、注入检测、模拟定位检测、native 交叉校验） |

工程化参考实现见本仓库 `defense/` 目录：
- `defense/server-side/run_evidence_validator.py`（证据校验 + 距离重算）
- `defense/server-side/trajectory_plausibility.py`（轨迹形态学）
- `defense/client-side/AntiMockDetector.kt`（模拟定位检测）
