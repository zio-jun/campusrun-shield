# 04 · 防护蓝图：如何保护校园跑类应用

> 核心判断：**客户端检测是过滤器，服务端交叉校验才是裁决者。**
> 两种攻击方式都能改写客户端看到的世界，但改不掉"物理世界的一致性"与"群体统计规律"。

## 0. 分层总览

```
第0层 设备与环境（客户端）   ← 模拟器/注入/root/mock 信号，低成本过滤
第1层 数据采集（客户端）     ← 关键指标 native 化 + 结果签名，抬高改写成本
第2层 上报通道（传输）       ← 签名、nonce、时间窗、证书绑定
第3层 数据真实性（服务端）   ← 轨迹物理/地图匹配/传感器交叉/环境一致性  ← 决定性防线
第4层 群体与行为（服务端）   ← 轨迹指纹、相似度聚类、账号/设备画像
第5层 证据链与处置           ← 心跳+抽查+人脸活体+阶梯处罚
```

## 1. 第 0 层：设备与环境检测（客户端）

| 检测项 | 实现要点 | 对应攻击 |
|---|---|---|
| mock 定位标志 | `LocationManager.isFromMockProvider()` + 高德 `AMapLocation.isMock()` + mock 应用包名黑名单 | A |
| 定位源偏差 | 系统定位 vs 高德融合结果经纬度偏差 > 阈值 → 可疑 | A |
| 注入特征 | `/proc/self/maps` 搜 frida/gadget/xposed、`/proc/self/status` TracerPid≠0、27042 端口、已知工具包名 | A/B |
| 完整性自校验 | APK 签名 + `classes.dex` CRC/哈希（壳 DA2Lock 已实现，实测有效） | A |
| 模拟器/VM 指纹 | `Build.HARDWARE/FINGERPRINT`、传感器数量型号、基带/蓝牙/相机特征、IMEI 空洞 | B |
| 设备认证 | Play Integrity / 厂商安全能力，作为信号而非唯一判据 | B |

**注意**：客户端只做"信号采集 + 上报 + 阶梯处置"，不要一次性硬阻断——否则攻击者能快速二分阈值。

## 2. 第 1 层：数据采集加固（客户端）

- 计步/里程/配速等关键指标在 **native 层**计算，Java 层只取结果（抬高 Hook 成本）
- 指标结果附 **HMAC 签名**（密钥白盒化/加固），服务端验签
- 采样数据带设备时间 + 单调时钟 + 采样序号，异常跳变即标记

参考实现：`defense/client-side/native/metric_guard.cpp`、`defense/client-side/IntegrityGuard.kt`

## 3. 第 2 层：上报通道

- 全部接口 HTTPS + 证书绑定（Pinning）
- 请求参数签名 + nonce + 时间窗（±5 分钟）+ 重放防护
- 成绩提交与心跳上报分离，服务端以心跳为基准做"过程证据"

## 4. 第 3 层：数据真实性（服务端 · 决定性）

### 4.1 轨迹物理合理性
- 速度上限：瞬时 > 8~10 m/s 标记（跑步合理 2~5 m/s）
- 加速度/急停：|Δv| 超限、方向突变角度阈值
- 采样间隔：位置点间隔异常（过大/恒定）标记
- 平滑度：卡尔曼残差/曲率突变

### 4.2 地图匹配（map-matching）
- 轨迹点到路网/操场地块的距离分布（操场跑道圆角矩形/400m 标准跑道）
- 跑出操场边界、穿越建筑 → 可疑

### 4.3 传感器–GPS 交叉
- 步频 × 步长（跑步 0.8~1.5 m/步）≈ GPS 速度
- 加速度计能量谱与速度相关性；海拔/气压变化与轨迹一致性
- 步频恒定值（如恰好 180 spm）且无自然波动 → 伪造特征

### 4.4 环境一致性
- IP 归属地/基站/WiFi BSSID 与 GPS 城市不符 → 标记
- 设备时间与服务器时间偏移、上传延迟分布异常
- 定位类型/卫星数/精度与场景不符（如卫星数恒为 12）

### 4.5 证据链
- 每 100~200m 心跳上报（含签名与序号）
- 随机抽查点：跑步中弹窗要求拍摄/签到
- 起终点 + 中途人脸活体（动作序列：眨眼/转头/张嘴）
- 全部结果入库形成"过程证据"，支持复议

## 5. 第 4 层：群体与行为分析

- 轨迹指纹：归一化重采样后哈希，检测**完全重复轨迹**（代跑流水线特征）
- DTW 相似度聚类：多人共用同一路线模板 → 异常簇
- 同设备多账号、同账号多设备、速度分布 KS 检验
- 成绩提交时间聚类（同一分钟大量提交 → 机器人）

## 6. 第 5 层：处置策略（阶梯）

1. **信号** → 悄悄记录 + 提高抽查概率
2. **可疑** → 标记成绩"待复核"，不直接作废
3. **复核** → 二次人脸/人工审核
4. **确认** → 成绩作废 + 通知 + 申诉入口

原则：阈值动态化、不公开、按风险分级；避免"检测即封杀"导致对抗升级与误伤。

## 7. 防误伤

- 弱 GPS 场景（地下室/隧道/高楼）：以传感器交叉为准，放宽轨迹阈值
- 设备无 GNSS 芯片/低端机：降级到基站定位，轨迹精度阈值自适应
- 隐私：只采集判定必需字段，人脸数据加密存储、限期删除

## 8. 天花板与结论

- 单靠客户端检测：可被方式一（无 root 注入）绕过
- 客户端 + 服务端交叉：方式一需同时伪造步频（做不到）→ 被交叉校验识破
- 方式二可伪造传感器，但受模拟器指纹 + 设备认证拦截
- 最终结论：**服务端持续性交叉校验 + 证据链 + 阶梯处置**是唯一可持续的防线
